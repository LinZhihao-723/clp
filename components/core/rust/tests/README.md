# Ground-truth corpus for the Rust clp-s reader

This corpus was built from the C++ `clp-s` so that the Rust reader can be checked against it.
Every archive here was written by the C++ binary. Every oracle is what the C++ binary printed for
that archive. Rust tests read the archives and compare their own output with the oracles.

- **C++ build:** `build/core/clp-s` and `build/core/log-converter`, branch `timeline_size_config`,
  commit `78795ed1`. The binaries' sha256 values are recorded in every manifest's `[build]` table.
- **Archive format:** 0.5.1 (magic `fd2fc530`) for every archive.

## Layout

```
tests/
  fixtures/
    fixtures.toml        hand-written fixture matrix (input x clp-s c flags)
    inputs/              JSONL inputs (hand-written, plus three generated by scripts/gen_inputs.py)
    archives/            C++ archives: <fixture>.clps, or <fixture>.<k>.clps when split
      reject/            archives the Rust reader must reject with UnsupportedArchive
      index.toml         GENERATED: build info, files and clp-s stats per fixture
    oracles/             GENERATED: C++ `clp-s x` output per readable archive (<archive stem>.jsonl)
    manifest.toml        GENERATED: one [[archive]] per archive file (expectation, oracle, sha256)
  queries/
    suite.toml           hand-written query suite (fixture and dataset queries)
    datasets.toml        GENERATED: dataset archives and their `x` oracles (counts, sha256)
    oracles/
      <id>.jsonl         GENERATED: C++ `clp-s s` stdout for fixture queries
      msgpack/<id>.msgpack, <id>.json      C++ `file --path` output, raw and decoded
      results-cache/<id>.json              C++ results-cache documents (MongoDB canonical JSON)
      manifest.toml      GENERATED: one [[oracle]] per (query, output)
```

Large artifacts live under the data root, `$PROTO_DATA_ROOT`. When the variable is unset, the
data root is `target/proto-data` in this workspace (ignored by git). `clp-s-difftest` also takes
`--data-root`.

- `datasets/{bench,spider,synthetic}.clps`: the dataset SFAs.
- `oracles/datasets/<name>.x.jsonl`: the C++ `x` output of each dataset.
- `oracles/queries/<id>.jsonl`: the C++ stdout of each dataset query.
- `work/`: scratch space of the scripts and of `clp-s-difftest`; `perf/`: performance results.
- `venv/`: the Python environment of the scripts.

The repo side keeps only their counts and checksums, in `queries/datasets.toml` and
`queries/oracles/manifest.toml`, which store these paths relative to the data root. Tests and
`clp-s-difftest` resolve them against the data root, so the datasets can be moved by moving the
whole directory. The fixture corpus under `tests/` does not depend on the data root.

## Regenerating

```bash
scripts/build-fixtures.sh            # inputs (generated ones) + every fixture archive
scripts/gen-oracles.sh               # all oracles: fixtures, datasets, queries
scripts/gen-oracles.sh fixtures      # only fixture `x` oracles
scripts/gen-oracles.sh queries       # only fixture query oracles (needs docker for results-cache)
scripts/gen-oracles.sh datasets      # dataset archives + `x` oracles
scripts/gen-oracles.sh dataset-queries
```

The scripts need the following.

- **C++ binaries:** `CLP_S` and `LOG_CONVERTER`, by default `build/core/clp-s` and
  `build/core/log-converter` of this repository (built with `task core`). `clp-s-difftest` and
  the Rust tests that run C++ also read `CLP_S`; `clp-s-difftest --cpp-clp-s` overrides it.
- **Dataset inputs** (only for `gen-oracles.sh datasets`, which compresses them): the suite names
  them through environment variables.
  - `PROTO_BENCH_JSONL`: the `bench` JSON-lines file (1,000,000 records, `timestamp` key).
  - `PROTO_SPIDER_FILE_LIST`: a text file listing the Spider `tracing` JSON-lines logs of the
    `spider` dataset, one path per line (9 files, `timestamp` key).
  - `PROTO_SYNTHETIC_JSONL`: the `synthetic` JSON-lines file (`ts` key). Generate it with
    `python3 -I scripts/gen_synthetic.py <OUT_PATH> 500000` (fixed seed 20261017).

  `datasets.toml` records only the input file names; check the `input_records`, `x_records` and
  checksums there after regenerating.
- **Python environment:** `uv`. The scripts create a venv at `$PROTO_DATA_ROOT/venv` with
  `msgpack==1.1.0`, `pymongo==4.10.1` and `tomli==2.0.2`.
- **Docker:** the image `mongo:8.0.21`. The scripts start a throwaway container named
  `proto-mongo-oracle` on `127.0.0.1:27917` and remove it afterwards.

Rebuilding the archives gives them new internal UUIDs and new bytes, but the records and query
results stay the same. Regenerate the oracles after every rebuild, because the manifests pin each
archive's sha256.

Variant flags:

| variant | flags |
|---|---|
| default | (none) |

Rejection fixtures in `archives/reject/`:

- `scalars.mfa/`: a multi-file archive directory (`clp-s c` without `--single-file-archive`).
  Rust must return `UnsupportedArchive`.
- `arrays.structurize-arrays.clps`: an SFA compressed with `--structurize-arrays`, so its schema tree
  has `StructuredArray` nodes. Rust must return `UnsupportedArchive` at open time, before it
  produces any result.

C++ reads both rejection fixtures successfully (`cpp_x_exit = 0`, with the record counts in the
manifest). The rejection comes from the prototype's scope, not from the archive format.

## Comparing records: the canonical form

C++ output order follows table order, and C++ key order follows node ids. Compare result sets as
**multisets of canonical lines**:

1. Parse each line as JSON. Keep every number as its verbatim token text, and keep duplicate keys.
2. Serialize the parsed value:
   - sort object keys by Unicode code point (UTF-8 byte order), keeping duplicates in their
     original order;
   - keep arrays in order;
   - write numbers as their original token;
   - escape strings minimally: `"`, `\`, `\b \f \n \r \t`, and other U+0000..U+001F as `\u00xx`
     with lowercase hex; nothing else is escaped, not even `/`, DEL or non-ASCII;
   - use no whitespace.
3. `canonical_sha256` is the sha256 of the sorted lines (bytewise), each followed by `\n`.
   `sha256`/`oracle_sha256` is the sha256 of the raw C++ output file.

`scripts/corpus.py canonical-sha FILE` prints both the count and the canonical sha of any JSON-lines
file.

- **Retained float formats:** with FormattedFloat and DictionaryFloat values (the default
  `--retain-float-format`), C++ prints the original float text. The canonical form is therefore
  exact.
- **Plain floats** (the `nofloat` variants): C++ prints `%f`, which is lossy (DV-01), and Rust
  prints shortest round-trip. Compare floats numerically there, and expect `%f` artifacts in the
  oracle: `1e-7` prints as `0.000000`, and `1e300` prints in full.
- **Unstructured arrays** print their original raw JSON text, inner whitespace included, in both
  C++ and Rust. The canonical form normalizes that whitespace. A byte-exact comparison would not.

## The query suite

Each `[[query]]` in `queries/suite.toml` has an `id`, a `target` (a fixture name, meaning all of its
archives searched as one session, or `dataset:<name>`), `kql`, and optionally `ignore_case`,
`tge`/`tle` (epoch ms), `projection`, `outputs` and `max_num_results`. Multi-archive targets run in
C++ as one `clp-s s <dir>` over a directory of symlinks to the archives.

- **Divergences.** A query whose C++ result is a registered divergence (design.md Part 1 §8.3) has
  `divergence = ["DV-xx", ...]`. It also states the Rust result it expects:
  - `expected_rust_ids`: the `rid` (search), `kid` (keys) or `id` values of the expected records;
  - `expected_rust_count`: used for fixtures without ids, and for datasets;
  - `expected_rust_exit = 0`: used for DV-20.
- **Non-divergent queries** must match the C++ oracle exactly, as a canonical multiset.
- **Reference model.** `scripts/reference_eval.py` is an independent Python model of design.md
  Part 3: K3 over existential predicates, istringstream literal typing, wildcards that descend
  into arrays, epoch-ms numeric literals against the timestamp column, ns-exact time bounds, and
  ASCII case-folding. `gen-oracles.sh` runs it on every fixture query and writes
  `reference_status` into the manifest:
  - `match`: no tag, and the model equals C++;
  - `registered-divergence`: tagged, the model equals `expected_rust_*`, and C++ differs from it;
  - `skipped`: projection queries.

  Any other status is printed as `REFERENCE CHECK: ...` and needs a decision. The model reads its
  records from the archive itself, through C++ `s '*'` with the msgpack output, so it sees the
  stored values: wrapped u64s, and timestamps as the C++-decoded epoch.
- **Wire oracles.**
  - **msgpack** (`file --path`): one array per result, `[timestamp_ms, message, orig_file_path,
    archive_id, log_event_idx]`. `message` is the JSON line plus `\n`. For SFAs, C++ writes an empty
    `orig_file_path`, and an `archive_id` equal to the archive's file name.
  - **results cache** (`results-cache --max-num-results N`): documents shaped
    `{_id: {archive_id, log_event_idx}, dataset, message, orig_file_path, timestamp}`, dumped as
    MongoDB canonical extended JSON and sorted. `wire-cache-split` shows C++'s per-archive top-k
    (90 documents from 9 archives, DV-25). `wire-cache-nolog` shows the `_id` collision without
    log order (1 document survives, DV-24). `wire-msgpack-split` shows the per-archive truncation of
    the output file (only the last archive's tuples survive, DV-21).
  - **Who judges them.** `clp-s-difftest queries` judges the msgpack oracles for every reader
    (the Rust library through `MsgpackResultSink`, `clp-s-rs` through `--output file`). It skips
    the results-cache oracles for the Rust readers, because they need a MongoDB server. Those are
    judged by `clp-s-cli/tests/outputs.rs` (`results_cache_outputs_match_the_cpp_oracles`, through
    the same harness) and `clp-s-results-cache/tests/results_cache.rs`, both opt-in through
    `crates/clp-s-results-cache/scripts/run-mongo-tests.sh`.

## C++ behaviours observed while building the corpus

These are facts about the C++ binary that the Rust reader must reproduce, or that explain an
oracle.

- **u64 integers wrap to i64 at ingestion.** `18446744073709551615` is stored and printed as `-1`.
  Inside an unstructured array the raw text survives, but C++ array search also wraps it:
  `a: -1` matches (`arrays-u64-elem`). §8.3 has no entry for this. The Rust reader must match it,
  or a DV entry must be added.
- **Lone surrogates** (`\ud800`) are stored as U+FFFD. `-0` (integer) is stored as `0`, while the
  float `-0.0` keeps its sign.
- **Float timestamps:** `1700000004.0` and `.00` fail compression ("Failed to parse timestamp"),
  while `.000`, `.5` and `.123` work, and so does scientific notation in a non-timestamp column. A
  float ms value at the timestamp key (`1700000008123.5`) is read as seconds, overflows, and
  decompresses as `2899553342.221251328` (`timestamps-float.ts`, id 8). The oracle records what
  C++ stored.
- **Unparsable string timestamps** abort compression. Every string timestamp in this corpus
  therefore parses.
- **`--tle` compares at ns precision.** `1700000006.999999` s is excluded by
  `--tle 1700000006999` (`time-float`).
- **Records with a duplicate key** (`{"a":1,"a":2}`) are silently dropped at ingestion. They are
  not part of the corpus.
- **Timestamps in kv-IR archives:** in the archives ingested from kv-IR, `timestamp` is a plain
  string unless `--timestamp-key timestamp` is given. Without that flag, every tuple carries
  `timestamp_ms = 0`.

## Counts

The authoritative numbers are in the GENERATED manifests.

- **Fixtures:** 49 fixtures, built into 59 archive files: 57 readable archives with 57 `x` oracles,
  and 2 rejection fixtures.
- **Queries:** 342 queries with 342 C++ oracles.
  - 303 fixture queries with stdout oracles;
  - 4 msgpack-file oracles and 3 results-cache oracles;
  - 32 dataset queries: the 28 queries of the C++ baseline list plus 4 extras. Their oracles
    (2.9 GB) are under `PROTO_DATA_ROOT`.
- **Divergences:** 79 queries are tagged with DV-05, 06, 07, 08, 09, 10, 11, 12, 13, 14, 15, 16,
  17, 19, 20, 21, 24, 25, 36, 37, 38, 39 and 47.
- **Reference model:** it agrees with C++ on 224 untagged fixture queries. On the 75 tagged
  fixture queries it checks, it agrees with the stated Rust expectation. It also reproduces the
  figures of design.md Part 1 on the datasets: 750,396 for `NOT ERROR` on bench, and 30,781 for
  `payload > 50000` on synthetic.
